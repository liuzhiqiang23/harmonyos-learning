# backend-demo：跨端共用的最小后端

这个后端是**鸿蒙端和以后微信小程序端共用的同一个服务**——同一套接口、同一份数据。
之所以专门拆出来，是因为写客户端时"后端换个平台就得重写"是没必要的工作量。

## 启动

最简单：双击 `start-server.cmd`。

或者命令行：

```bash
cd D:\harmonyos-learning\backend-demo
python server.py
```

启动后会打印两个地址：

- `http://127.0.0.1:8787/api/movies` —— 本机访问，**DevEco 预览器用这个**
- `http://192.168.x.x:8787/api/movies` —— 局域网地址，**真机/手机用这个**（手机和电脑要在同一 WiFi）

浏览器直接打开 `http://127.0.0.1:8787/` 能看到一张表格，用来确认后端活着。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/movies` | 返回全部电影 |
| GET | `/api/movies/{id}` | 返回单条，例如 `/api/movies/3` |

返回结构统一为：

```json
{ "code": 0, "message": "ok", "data": [ ... ], "total": 8 }
```

## 为什么用纯标准库

只用了 Python 自带的 `http.server` + `json`，**不需要 pip 装任何东西**，
换台电脑拷过去就能跑。真实项目里会换成 Flask / FastAPI / Spring Boot 之类，
但接口形状是一样的，客户端代码不用改。

## 以后小程序端怎么接

微信小程序的 `wx.request` 调同一个地址即可。但要注意小程序有两条硬性要求：

1. **正式上线必须 HTTPS**，且域名要在微信公众平台配置为 request 合法域名；
2. 开发阶段可以在开发者工具里勾"不校验合法域名"先用 `http://127.0.0.1` 跑通逻辑。

所以本机 `http://127.0.0.1:8787` 只适合开发调试，上线前一定要换成有备案的 HTTPS 域名。
